# Custom Codex UI 1.8.2

This patch fixes launch failures after Microsoft Store updates and restores the
default sidebar layout without changing Codex's native controls.

- Prefer the currently registered, signed Store installation over an older
  executable that is still running or saved in machine settings.
- Recover a verified older session after Store removes its package manifest;
  never try to restart a retired executable with missing installation metadata.
- Require the real main app surface to be visible before reporting foreground
  launch readiness. Restore it through the native host before trying the
  same-profile executable entry point. Detached and overlay pages cannot satisfy
  readiness, and their theme exclusions remain in place.
- Keep session state and restore the theme watcher when graceful quit fails.
  Restore verifies the recorded owner independently of the current installation.
- Report low disk space explicitly. Keep theme-owned temporary files on the
  installation volume and preserve the selected conversation history location.
- Open the sidebar once per document while retaining later manual collapse.
  Fit all nine character compositions and decorative frames inside the main
  workspace, leaving room for the native sidebar.
- Support Codex Store packages 26.1021.2667.0 and 26.1021.3705.0. Future package
  versions continue to require compatibility verification.

The portable package contains all nine themes and excludes sign-in profiles,
conversation history, local settings and development outputs. Extract it into a
local writable folder and run Setup.ps1. Finish active work before closing an
older themed client; retain its profile and agent storage when updating.

The themed session exposes an unauthenticated debugger on a random loopback
port while running. Random ports do not authenticate local access. Use only on
a trusted computer and never forward the debugger port.
